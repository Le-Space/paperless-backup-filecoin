PAPERLESS-NGX BACKUP TO FILECOIN ONCHAIN CLOUD - STEP BY STEP
=============================================================

What you get: once a week your whole Paperless archive (documents + database),
encrypted on your machine, stored with several independent hosters in Europe
at the same time. Each hoster proves on chain every day that it still holds it.

Time: about 30 minutes, most of it for getting USDFC.
Cost: about USD 0.12 per hoster per month plus USD 2.50 per TiB.


1. INSTALL
----------

    git clone https://github.com/Le-Space/paperless-backup-filecoin.git
    cd paperless-backup-filecoin
    npm install
    cp config.example.json config.json

The script expects to sit next to your docker-compose.yml (one folder below
the Paperless folder). Elsewhere, set PAPERLESS_DIR to the Paperless folder.
If your Paperless service is not called "webserver", set PAPERLESS_SERVICE.


2. CHOOSE REGION AND NUMBER OF COPIES
-------------------------------------

Edit config.json:

    "regions": "EUROPE",    EU, EEA, EUROPE (EEA + UK + CH), or ["FR","PL","DE"]
    "copies": 3,            how many hosters hold a copy
    "providerIds": [],      or name them yourself, e.g. [36, 37, 1]

See who is available and who would be chosen:

    node backup.mjs providers

Columns: id | chosen | inside your region | endorsed/approved | active | location | name
The location is what the hoster declares itself; it is not verified.


3. CREATE THE ENCRYPTION KEY
----------------------------

    node backup.mjs init-key

macOS: the key goes into the keychain. Linux: first set where it goes, e.g.

    export AGE_IDENTITY_FILE=$HOME/.config/paperless-backup/age-identity.txt

IMPORTANT: keep a second copy of this key outside the machine (password
manager, paper). Without it no backup can be read. On macOS print it with:

    security find-generic-password -s paperless-backup-age-identity -a "$USER" -w


4. DRY RUN (NOTHING IS UPLOADED)
--------------------------------

    node backup.mjs plan

This exports Paperless, encrypts the export, checks that the key decrypts it,
and prints size, chosen hosters and the monthly estimate.


5. TRY IT ON THE TESTNET FIRST (FREE)
-------------------------------------

Filecoin's Calibration testnet works like mainnet, with free test tokens.
A full round - fund, upload, verify, restore - costs nothing.

    cp config.calibration.example.json config.calibration.json
    node backup.mjs init-key        (skip if you already did step 3)

Copy "ageRecipient" from config.json into config.calibration.json.

Make a throwaway testnet wallet. It is printed only as an address; the key
goes into a file only you can read:

    node -e 'import("viem/accounts").then(({generatePrivateKey,privateKeyToAccount})=>{const k=generatePrivateKey();require("fs").writeFileSync("testnet-wallet.key",k+"\n",{mode:0o600});console.log(privateKeyToAccount(k).address)})'

Get test tokens for that address:
  - tFIL (gas):     https://faucet.calibnet.chainsafe-fil.io/funds.html
  - tUSDFC (storage): https://forest-explorer.chainsafe.dev/faucet/calibnet_usdfc

Then run everything against the testnet:

    export BACKUP_CONFIG=config.calibration.json WALLET_KEY_FILE=testnet-wallet.key
    node backup.mjs providers
    node backup.mjs status
    node backup.mjs fund 1
    node backup.mjs run
    node backup.mjs verify
    node backup.mjs list
    node backup.mjs restore <pieceCid> restore-test.zip
    unset BACKUP_CONFIG WALLET_KEY_FILE

Testnet backups are recorded in ledger.calibration.json, apart from real
ones. The testnet has few providers and no region choice worth the name;
it is for checking the procedure, not for keeping data.


6. WALLET AND MONEY (MAINNET)
-----------------------------

What the script pays with:
  - USDFC, a dollar stablecoin on Filecoin, for storage. About 10 USDFC
    last many months for an archive of a few GiB.
  - A little FIL for transaction fees; about 0.5 FIL is plenty.
There is no card payment.

Getting USDFC (with FIL in a wallet such as MetaMask on the Filecoin network):
  - SushiSwap on Filecoin: swap FIL for USDFC (pair FIL/USDFC, V3).
    The simplest way. Watch the price impact on small pools.
  - Squid Router (https://app.squidrouter.com): swap or bridge from other
    chains and tokens to USDFC.
  - The USDFC app (https://app.usdfc.net) mints USDFC against FIL collateral.
    That is a loan: if FIL falls, the collateral can be liquidated. Not worth
    it for a few dollars of storage.
No FIL yet? Buy it at an exchange and withdraw it to your wallet on the
Filecoin network.

USE A SEPARATE WALLET FOR THE BACKUP. The script holds its private key, so
whoever gets into the machine could empty that wallet. In MetaMask:
  1. "Add account" - a new account only for the backup.
  2. In your main account, swap FIL for 10-15 USDFC.
  3. Send the USDFC and about 0.5 FIL to the backup account.
  4. Give the script only the backup account's key
     (MetaMask: account details > show private key).

Store that key for the script.
macOS (hidden prompt):

    security add-generic-password -s paperless-backup-filecoin-wallet -a "$USER" -w

Linux: put it in a file only you can read and set WALLET_KEY_FILE to it.

Then:

    node backup.mjs status      balances and whether the account is ready
    node backup.mjs fund 3      deposit for about three months of runway


7. FIRST BACKUP (MAINNET)
-------------------------

    node backup.mjs run
    node backup.mjs verify
    node backup.mjs list


8. EVERY DAY, AUTOMATICALLY - ONLY WHEN SOMETHING CHANGED
---------------------------------------------------------

    node backup.mjs daily

does, at most once a day:
  1. asks Paperless whether documents, notes or labels changed since the last
     backup (no change and the last full upload is less than a week old:
     nothing is uploaded);
  2. otherwise run + verify, then prune (if "daily.prune" is true);
  3. mails a short report: what happened, copies, wallet, and how many days
     the Filecoin Pay deposit lasts (warns below "daily.warnRunwayDays").
Started again the same day, it exits quietly. A failure is retried on the
next start and mailed once a day.

Settings in config.json:

    "daily": { "time": "03:30", "fullEveryDays": 7, "prune": true, "warnRunwayDays": 30 },
    "mail":  { "host": "smtp.example.com", "port": 465, "user": "backup@example.com",
               "from": "backup@example.com", "to": "you@example.com" }

The SMTP password, macOS (hidden prompt):

    security add-generic-password -s paperless-backup-smtp -a "$USER" -w

Linux: a file only you can read, named by SMTP_PASSWORD_FILE. Without
"mail" or a password the report only goes to backup.log.

macOS (launchd): start at 03:30, every hour, and at login. The first start
after 03:30 does the work, so a Mac that was off at night catches up within
the hour after it is on. Save as
~/Library/LaunchAgents/paperless-backup-filecoin.plist, adjust the paths, then:
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/paperless-backup-filecoin.plist

    <?xml version="1.0" encoding="UTF-8"?>
    <!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
    <plist version="1.0"><dict>
      <key>Label</key><string>paperless-backup-filecoin</string>
      <key>ProgramArguments</key><array>
        <string>/bin/sh</string><string>-c</string><string>node backup.mjs daily</string>
      </array>
      <key>WorkingDirectory</key><string>/path/to/paperless-backup-filecoin</string>
      <key>EnvironmentVariables</key><dict>
        <key>PATH</key><string>/path/to/node/bin:/usr/local/bin:/usr/bin:/bin</string>
      </dict>
      <key>StartCalendarInterval</key><dict>
        <key>Hour</key><integer>3</integer><key>Minute</key><integer>30</integer>
      </dict>
      <key>StartInterval</key><integer>3600</integer>
      <key>RunAtLoad</key><true/>
      <key>StandardOutPath</key><string>/path/to/paperless-backup-filecoin/backup.log</string>
      <key>StandardErrorPath</key><string>/path/to/paperless-backup-filecoin/backup.log</string>
    </dict></plist>

Docker must be running; until it is, each hourly start fails and retries.

Linux (cron), every hour (the script itself decides when the day's run is due):

    0 * * * *  cd /path/to/paperless-backup-filecoin && export WALLET_KEY_FILE=... AGE_IDENTITY_FILE=... SMTP_PASSWORD_FILE=... && node backup.mjs daily >> backup.log 2>&1

Cleaning up by hand (irreversible; the newest complete backup always stays):

    node backup.mjs prune          shows what would go
    node backup.mjs prune --yes    deletes it


9. RESTORE
----------

On the same machine:

    node backup.mjs restore <pieceCid>

On a new machine: bring ledger.json and the age key, then

    AGE_IDENTITY_FILE=key.txt node backup.mjs restore <pieceCid>

Without a wallet the script downloads from the hosters' public piece URLs.
Unzip the result and import it into an empty Paperless:

    docker compose exec webserver document_importer ../export/<unzipped-folder>


10. GOOD TO KNOW
----------------

- A hoster that stops answering during the upload: run retries with the
  next chosen hoster as the one you upload to; the others copy from it.
- "EIP2612: expired deadline" when funding: your computer's clock is off.
  Switch on automatic date and time, then fund again.
- Too few hosters in your region? The backup stops instead of storing
  elsewhere. Widen "regions" or lower "copies".
- A hoster dropped from the approved list? Same: the run stops and says which.
- Keep at least one more copy elsewhere (NAS, object storage with object lock).
  This is one leg of a 3-2-1 backup, not all of it.


11. WHAT THE OUTPUT SHOULD LOOK LIKE
------------------------------------

The lines come from real runs on mainnet and on the Calibration testnet;
addresses, hashes, ids and amounts are examples. Times are UTC. If yours
looks like this, it worked.

providers - who would be chosen (columns: id | chosen | in region |
tier | active | declared location | name):

    $ node backup.mjs providers
      1 | chosen | region | endorsed | active | C=GB;ST=Gloucestershire;L=Cheltenham | ezpdpz-main
      5 |        |        | endorsed | active | C=US;ST=California;L=Chino | Mongo2Stor Mainnet
     36 | chosen | region | endorsed | active | C=FR;ST=Grand Est;L=Strasbourg | Cello
     37 | chosen | region | endorsed | active | C=PL;ST=Mazowieckie;L=Warsaw | Bass

plan - dry run, nothing leaves the machine:

    $ node backup.mjs plan
    2026-10-04T11:32:33.060Z exporting Paperless …
    2026-10-04T11:34:21.672Z decryption check: ok
    2026-10-04T11:34:21.673Z paperless-2026-10-04: 631848030 bytes encrypted (0.59 GiB)
    2026-10-04T11:34:21.673Z providers: 36 Cello (C=FR;...); 37 Bass (C=PL;...); 1 ezpdpz-main (C=GB;...)
    2026-10-04T11:34:21.673Z estimate: ~0.364 USD per month for 3 copies (...)

status - before funding (FIL > 0 is needed for fees):

    $ node backup.mjs status
    2026-10-05T10:06:19.000Z network Filecoin - Mainnet, account 0xYourBackupAccount…
    2026-10-05T10:06:19.700Z wallet: 1 FIL, 10.38 USDFC; available in Filecoin Pay: 0 USDFC
    2026-10-05T10:06:21.415Z for 1 GiB on providers 36, 37, 1: 0.367 USDFC per month
    2026-10-05T10:06:21.415Z not ready: deposit 1.867 USDFC needed (node backup.mjs fund)

fund - one transaction, deposit and approval together:

    $ node backup.mjs fund 3
    2026-10-05T10:08:35.670Z rate 0.3746 USDFC per month for 2 GiB on 3 providers
    2026-10-05T10:08:35.673Z depositing 2.9986 USDFC and approving the storage service …
    2026-10-05T10:09:40.000Z confirmed: 0x<transaction hash>

status - after funding:

    $ node backup.mjs status
    2026-10-05T10:12:45.332Z wallet: 0.99996 FIL, 7.388 USDFC; available in Filecoin Pay: 2.9986 USDFC
    2026-10-05T10:12:46.769Z for 1 GiB on providers 36, 37, 1: 0.367 USDFC per month
    2026-10-05T10:12:46.769Z ready to upload

run - export, encrypt, upload (minutes, depending on size and uplink):

    $ node backup.mjs run
    2026-10-05T10:13:01.402Z exporting Paperless …
    2026-10-05T10:14:46.855Z uploading 631848030 bytes to providers 36, 37, 1 (primary 36) …
    2026-10-05T10:24:03.413Z piece bafkzcib…: 3/3 copies

  If a provider does not answer, you see a retry with the next one first:
    … upload with primary 36 failed: Failed to store piece on service provider 36 (…)
    … uploading 631848030 bytes to providers 37, 1, 36 (primary 37) …

verify - every copy in its data set:

    $ node backup.mjs verify
    2026-10-05T10:24:29.563Z ok      data set 1695 (provider 36) bafkzcib…
    2026-10-05T10:24:30.304Z ok      data set 1694 (provider 37) bafkzcib…
    2026-10-05T10:24:30.977Z ok      data set 1696 (provider 1) bafkzcib…

list:

    $ node backup.mjs list
    2026-10-05 | complete | bafkzcib… | 603 MiB | 36@C=FR 37@C=PL 1@C=GB

daily - a day without changes (the mail carries the same lines):

    $ node backup.mjs daily
    2026-10-05T10:25:03.271Z No change in Paperless since the backup of 2026-10-05 10:24 UTC; nothing uploaded.
    2026-10-05T10:25:05.089Z Wallet 0.99996 FIL, 7.388 USDFC; Filecoin Pay 1.134 USDFC available, about 93 days of runway.

restore - downloaded, checksum checked, decrypted:

    $ node backup.mjs restore bafkzcib… restore-test.zip
    2026-10-05T06:53:40.649Z restored to restore-test.zip; import into an empty Paperless with: document_importer <dir-with-unzipped-export>

The restored zip contains every document unencrypted. Delete it when the
test is done.

Signs that something is wrong:
  "no wallet key"                  step 6: the key is not stored yet
  "invalid private key"            a seed phrase was stored instead of the
                                   account's private key (64 hex characters)
  "not ready: deposit … needed"    run node backup.mjs fund
  "Insufficient balance"           not enough USDFC (or no FIL for fees)
  "EIP2612: expired deadline"      the computer's clock is off
  "… not (or no longer) approved"  a chosen provider left the approved list
  "… copies wanted, but only …"    too few providers in your region
  "… (INCOMPLETE)"                 fewer copies than asked; run verify, then run again
